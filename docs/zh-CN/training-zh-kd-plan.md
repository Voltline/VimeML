# vimeml-zh-v2-20m 蒸馏计划

2026-11-16 起草。手机上只加载一个模型（见[发布范围](release-zh-v2-plan.md)），所以 v2-20m 必须能用自己的分数重打分。[200M 评测](reports/zh-200m-pinyin-eval-20261116/report.md)显示：

- r2-cont 用自己的分数重打分时只比 v1 单模型高 0.8（p = 0.49），拼音后训练削弱了它的 LM 能力；
- 12K 联合拼音 200M 生成和 LM 打分都好（自身重打分 58.8%，比 v1 高 6.2）。

本计划用这个 200M 做老师，在线蒸馏 20M，目标是在一个 20M 里同时得到生成能力和 LM 能力。

## 方法

- **老师**：`tiny-zh200m-12k-pinyin-pt-d1024/final.pt`（step 844,730，sha256 `90e48fe4…`），冻结，BF16，不求梯度，与学生吃同一个批次。两者共用 12K 分词器和拼音样本格式，可以直接做 token 级蒸馏。
- **损失**：在所有被监督的位置上，`(1 − α)·CE + α·T²·KL(老师_T ‖ 学生_T)`，α = 0.5，T = 1。plain 和四种拼音任务都蒸馏；`per_kind` 归一化不变。
- **数据和配方**：沿用 r2-base——v2 拼音数据（Rime 读音）、同样的混合比例（plain 160 / full 96 / mixed 128 / initials 96 / error 32）、同一个 seed `20261116`，所以数据顺序与 r2-base 完全相同。本轮只用 r1 数据，r2 留到下一轮。
- **代码**：[joint_zh_pinyin.py](../../src/vimeml/training/joint_zh_pinyin.py) 的可选 `[distillation]` 段。训练日志按任务类型记录 KL，开训前把老师自己的验证损失写进 `teacher_validation.json`。

## 两臂

| 臂 | 初始化 | 更新数 | 峰值 LR | warmup | 配置 |
| --- | --- | ---: | ---: | ---: | --- |
| `kd-base` | v1 基座 `tiny-zh13-12k-fresh-s1-d384-l9` | 90,000 | 3e-4 → 3e-5 | 2000 | [train-zh-pinyin-kd-base.toml](../../configs/train-zh-pinyin-kd-base.toml) |
| `kd-cont` | r2-cont final（step 60,000） | 30,000 | 1.5e-4 → 1.5e-5 | 1000 | [train-zh-pinyin-kd-cont.toml](../../configs/train-zh-pinyin-kd-cont.toml) |

- `kd-base` 与 r2-base 只差老师这一项，用来回答“蒸馏本身带来多少”。
- `kd-cont` 回答“老师能不能把 r2-cont 丢掉的 LM 能力补回来”，成本只有前者的三分之一。

## 判定

全部在 development 上进行，blind 和公开集 test 都不读。

1. **主指标**：公开拼音集 development，自身重打分（λ = 1.6）的 Top-1。与 v1 单模型（LM 模式）做句子簇 sign-flip 配对检验，必须显著更高。
2. **守门**：Standard 全拼重排的 Top-1 不能显著低于 v1。
3. **描述性**：联想 A–D 和私有基准，不决定去留。

两臂都通过时，主指标更高的那一臂作为 v2-20m 候选；两臂都没有通过，就在下一轮加入 r2 数据，或者调整 α、T。

## 第三轮（2026-11-17 起草）

[第二轮评测](reports/zh-kd-eval-20261117/report.md)选出了 `kd-cont`，但还有两处差距：

- 自身重打分 54.8%，老师是 58.8%；
- 联想轨道 A 的 Top-3 是 25.6，v1 是 27.6。

r2-cont 加 kd-cont 一共训了 90,000 步，r1 拼音数据已经重复了 3.7 到 5 遍（plain 1.9 遍）。第三轮的重点是加入没见过的 r2 数据，同时试两个针对上面差距的改动。

### r2 拼音数据

- 配置是 [data-zh-pinyin-r2.toml](../../configs/data-zh-pinyin-r2.toml)，输出到 `zh-pinyin-r2-12k`。
- 构建器、样本规则、分词器和 Rime 读音都与 r1 相同。label 改成 `zh-pinyin-r2`，所以文档选择和所有随机抽样都是新的。
- export-r2 没有 pools、没有记忆探针，也没有 LCCC，所以 r2 的每篇 train 网页文档都参与选择，plain 和拼音各取 0.8%。
- 规模是用同样的规则在 export-r1 上跑一个 row group 估出来的：
  - plain 约 1,300 万个窗口；
  - 每类拼音约 330 万条，是 r1 的 1.45 倍；
  - error 约 110 万条。
  第三轮在 r2 上读不到半遍。
- 在集群上构建，因为 export-r2 只在集群上。用同样的规则在本地 16 个进程上跑 97.9 万篇文档用了 16.5 秒，没有单一热点：拼音采样占 57%，读 parquet 占 18%。r2 约 8,300 万篇文档，CPU 时间约 3,000 秒，整体受读盘速度限制。
- r2 不含 LCCC，所以 r1 + r2 各占一半时，拼音样本里的对话占比从约 25% 降到约 13%。这个变化算在「加 r2」的整体效应里，由 r3-ctrl 对 r3-data 来衡量。

### 训练器

- `joint_zh_pinyin` 新增可选的 `[[data.extra]]`：额外目录有自己的配比和独立的取样流（排列种子末尾加上来源序号）。它的样本接在主目录同类样本之后，所以 `per_kind` 归一化不用改。
- 不配额外目录时，每一步的批次与修改前逐字节相同（已在 v2 拼音数据上验证）。
- 验证只读主目录（r1），所以各臂的验证曲线可以直接比较。
- 错字计划里的 `typo` 第二目录也走这个机制。

### 四臂

全部从 `kd-cont` final（step 30,000）出发，训练 30,000 步，峰值 LR 1e-4 → 1e-5，warmup 1000，老师不变，seed 改成 `20261117`。r2-cont 和 kd-cont 都是从 seed `20261116` 的第 0 步开始的，换 seed 才能避免把同样的数据顺序再走一遍。

| 臂 | 数据（每次更新，r1 + r2） | α | T | 回答的问题 |
| --- | --- | ---: | ---: | --- |
| `r3-ctrl` | 只用 r1：plain 160 / full 96 / mixed 128 / initials 96 / error 32 | 0.5 | 1 | 只多训 30,000 步能带来多少（对照） |
| `r3-data` | 每类 r1、r2 各一半，总量与 r3-ctrl 相同 | 0.5 | 1 | 新数据带来多少 |
| `r3-alpha` | 同 r3-data | 0.9 | 1 | 更多地拟合老师，能不能补回 LM 能力 |
| `r3-plain` | 同 r3-data，但 plain 从 160 提到 256（r1 128 + r2 128） | 0.5 | 1 | 专门补联想 |

T 固定为 1：重打分和联想用的都是 T = 1 时的概率，调高 T 等于让学生拟合一个用不上的分布。α 是更直接的旋钮。

### 判定

全部在 development 上进行，评测方法与第二轮相同。

1. 主指标最高的那一臂，在下面任一条件成立时取代 `kd-cont`：
   - 主指标（公开集自身重打分 Top-1）显著高于 `kd-cont`；
   - 主指标不显著低于 `kd-cont`，同时联想轨道 A 的 Top-3 达到 v1 的 27.6。
2. 守门不变：Standard 全拼重排的 Top-1 不能显著低于 v1。
3. 如果胜出的是 `r3-ctrl`，结论就是只靠多训就够了，后面不再加 r2。
4. 私有基准仍是描述性的。

第三轮选出的臂，就是[错字计划](training-zh-typo-plan.md)里加不加 `typo` 两臂的出发点。

### 第四轮：800M 当老师

800M 正式评测通过后，用第三轮胜出的配方，只把老师换成 800M（同一个 12K 词表，可以直接做 token 级蒸馏）。能赶上 v2-20m 定版就用在 v2-20m 上，赶不上就放到下一版。800M 前向的开销要等 800M 训起来后再测。
