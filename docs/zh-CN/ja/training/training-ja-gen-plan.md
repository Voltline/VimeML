# 日文生成路线（ja-gen）计划

2026-11-25 起草。本计划提交即注册第 0、1 阶段：这两个阶段只做评测集、数据、读音和词表，不训练模型。第 2 阶段以后在这里先定路线，每一阶段的臂、配置和判定规则在该阶段训练开始前补进本页；已注册的内容不改，之后的改动作为偏差记在页末。

## 目标

- 一个手机端约 20M 的日文模型同时做三件事：**假名 → 文字的整句生成**、对 AzooKey 候选重排、预测。生成是必选项。
- Vime 的候选列表由 AzooKey 候选和模型生成候选合并而成，合并后的每个候选用同一模型统一打分排序。
- 日文不单独做 800M。中日英多语 800M 放在最后，单独立计划（见[中文 v2 发布计划](../../zh/release-zh-v2-plan.md)末项）。
- [V4.5 集成蒸馏](training-v45-plan.md)撤下，不执行。
- 新模型通过确认之前，部署的仍是 V4.2 第 20 轮。

## 依据

**日文线卡在候选池。**

- Standard 开发集 728 条中，有 98 条的正确答案不在 AzooKey 前 20 个候选里，任何重排都救不回来；剩下的 Top-1 错误以书写形式差异为主（[错误分解](../reports/analysis-20261021/ime-errors.md)：池外 48%、书写形式 35–44%、语义 8%）。
- 重排配方已经饱和：V4.4 六臂都没有效果，seed 噪声带 501–523（[V4.4 结果](training-v44.md)）。四 seed 集成也只到 535，V4.5 的上限就是这 +21 左右。

**中文线验证过的做法：**

| 经验 | 中文结果 |
| --- | --- |
| 读音条件生成 + 用同一模型的 LM 分数自重排 | 公开拼音集所有输入 Top-1 31.0 → 49.1（[v2-20m 确认](../../zh/reports/zh-v2-confirmation-20261120/report.md)）；自重排单独贡献 39.5 → 51.3（[重排报告](../../zh/reports/zh-pinyin-rescore-20261115/report.md)） |
| 20M 先做纯 LM 预训练，再做读音后训练；不从头联合预训练 | 20M 联合预训练的生成比后训练差（私有集 −2.2，p 0.0004；[联合预训练记录](../../zh/reports/zh-pinyin-pt-20261115/record.md)） |
| 200M 联合读音预训练，再蒸馏到 20M | 200M 用自己的分数重排明显更强（[200M 评测](../../zh/reports/zh-200m-pinyin-eval-20261116/report.md)）；蒸馏后的 20M 公开集 +2.1（[蒸馏评测](../../zh/reports/zh-kd-eval-20261117/report.md)） |
| 口语后训练 | 口语集 39.0 → 42.3，公开集 49.1 → 51.4（[口语确认](../../zh/reports/zh-colloq-confirmation-20261123/report.md)） |
| 束搜索按按键位置分桶 | 只有消耗了相同按键数的假设互相比较，与 Vime 的实现相同；束宽 16 定为默认（[束搜索报告](../../zh/reports/zh-pinyin-beam-20261115/report.md)） |
| 与 v1 相同的 20M 结构 | Core ML 批量 KV v4 包（`prefix`、`score`、`scored`）和 Vime 接入原样复用，Mac 只需换推理包重跑（[v2-20m 任务说明](../../zh/mac/mac-zh-v2-20m.md)） |

**日文 V4.1 的读音任务失败，原因是做法不同：**

| 项 | V4.1 | 本计划 |
| --- | --- | --- |
| 读音的用途 | 给 AzooKey 候选打分时的条件输入 | 自己生成候选，并给合并后的候选打分 |
| 任务比重 | 0.2 × 转换损失 | 每次更新 320/512 条是读音样本（中文 r2 为 352/512） |
| 读音来源 | 两套词典的近似读音，分歧也保留 | 只保留 Sudachi 与 UniDic 整句一致的读音 |
| 排序 | 只用条件分数 | 生成分数 + λ × LM 分数 |

V4.1 在 Standard 上从 505 掉到 461（[V4.1 记录](training-v41.md)）。本计划第 2 阶段的 LM 对照组与读音组在 Standard 重排上的差，就是对这个问题的直接检验。

## 沿用中文线的设定（不再做消融）

- **结构**：词表 12,288，d384，九层，六头，SwiGLU 960，上下文 128，约 20M 参数；200M 用中文 200M 的形状（d1024）。
- **词表保留 id**：pad 0、unk 1、bos 2、eos 3、`<CTX>` 4、`<READ>` 5、`<OUT>` 6、`\n` 7，256 个字节 piece。
- **任务格式**：`[BOS, CTX] + 上下文 + [READ] + 读音 + [OUT] + 文字 + [EOS]`，损失只算 `<OUT>` 之后。读音是平假名串，按用户实际输入的样子连写（长音 ー、小假名、促音照原样）。
- **搜索**：束宽 16，按已消耗读音位置分桶，取前 10，结尾加 log P(EOS)；KV cache 必须支持。
- **重排**：`生成分数 + λ × LM 分数`，λ 起点 1.6，只在开发集上调，冻结后不再改。
- **配方**：20M 读音后训练用中文 r2-cont 配方（6 万步，lr 1.5e-4），蒸馏用 kd-cont 配方（α 0.5），口语后训练用 c40 配方。
- **不做**：错字纠正、ANE、词表大小扫描、多 seed 集成蒸馏。

## 第 0 阶段：评测

**0.1 候选池覆盖率。**

- 用现有 Standard 开发集的 AzooKey 导出（N-best 20），按长度和有无左文分层报告池外条目。
- 交给 Mac 再导出一次开发集的 N-best 50 和 100，固定与 v1 相同的转换器、词典、emoji 版本，其他设置不变。结果分开两类：加深候选池就能补回的条目，和只能靠生成补回的条目。
- 只用开发集，不导出、不读其他任何集。

**0.2 新公开集 `ime-kana-ja-v1`（假名 → 文字生成 + 重排）。**

- **来源**：WRIME ver2 和 JMultiWOZ，只用从未进入过以往任何日文评测集的作者、用户和对话（v1 开发、v1 reference、历史 regression 草稿、v2 盲测）。
- **片段规则**与 Standard 相同：同一消息内连续的 4–40 字片段，读音 4–64 个假名，左文不超过 64 字，不含拉丁字母、数字和 emoji；每个作者最多 20 条，每个对话最多一条。
- **分层**：片段长度 4–10 / 11–20 / 21–40 字 × 有无左文，轮流抽取。
- **读音**：Sudachi 与 UniDic 整句读音一致才收录（`src/vimeml/benchmarks/readings.py`），不做人工审核。读音统一成平假名。
- **重叠检查**：对日文训练文本做精确包含和 12 字锚点相似度扫描，与 Standard 相同；第 1 阶段新增的训练文本也要扫，命中的条目在冻结前去掉。
- **划分**：按作者 / 对话哈希一半一半分成 development 和 test，每份目标约 600 条。**test 封存**，只在第 5 阶段的预注册确认中读一次。
- **候选**：Mac 用部署设置（N-best 20）给两个划分各导出一次 AzooKey 候选，test 的候选导出后不打分。
- **指标**：
  - 主指标：最终显示列表的 Top-1，按 `notation.py` 的书写形式宽松判定；
  - 同时报告严格 Top-1、Top-3，以及按长度和有无左文分层的结果；
  - 统计按作者 / 对话聚类，沿用 [metrics v2](../benchmarks/metrics-v2.md)。
- **许可**：WRIME 是 CC BY-NC-ND 4.0，JMultiWOZ 是 CC BY-SA 4.0。条目文本只留在本地，仓库和公开发布只放汇总结果。

**0.3 开发集基线**（`ime-kana-ja-v1` development 和 Standard 开发集）：

- AzooKey 原序；
- V4.2 对 AzooKey 候选重排（现有部署方式）；
- 池上限（正确答案在池中的比例）。

**0.4 Standard 开发集 728 条**继续作为重排护栏，只做开发用途。

**第 0 阶段完成的标志**：覆盖率报告；`ime-kana-ja-v1` 冻结，manifest SHA256 写进本页；两个基线有数；test 未读。

## 第 1 阶段：数据、读音、词表

**1.1 语料。**

- 20M 的基础是 V4 的 LM 和聊天语料（`corpus-v4`、`corpus-v41-chat`），与 V4.2 相同。
- 200M 需要更多文本：从 FineWeb-2 `jpn_Jpan` 按固定 revision、固定步长选分片，跑与中文相同的清洗和质量筛选。目标是与中文 200M 相当的训练 token 数，分片清单和 token 数在构建时登记进本页。
- 只有 20M 用到的数据做 LLM 质量筛选，与中文 v2 的范围相同。

**1.2 读音。**

- 对每个训练片段同时用 Sudachi 和 UniDic 求读音，整段一致才作为读音样本；不一致的片段只作纯 LM 文本使用。
- 含拉丁字母、数字、符号等无法用假名输入的片段不做读音样本。
- 构建前先在 1 万句的抽样上报告一致率和分歧类型。一致率低于 60% 时停下来，换读音方案前另作偏差登记。

**1.3 样本种类与起始配比**（每次更新 512 条，第 2 阶段不做配比消融）：

| 种类 | 内容 | 每次更新 |
| --- | --- | ---: |
| `plain` | 纯 LM 文本 | 192 |
| `span` | 带同一消息左文的片段转换，即实际输入时的情形 | 192 |
| `sentence` | 无左文的整句转换 | 128 |

**1.4 词表**：在日文训练样本上训练 SentencePiece unigram 12,288，保留 id 见上。要求所有平假名、片假名都是单独的 piece，验证集来回编码无损。

**1.5 产出**：token 库 `ja-kana-v1-12k`，manifest SHA256 写进配置并登记；另存一份到私有存储。

**第 1 阶段完成的标志**：读音一致率报告；词表来回编码与假名覆盖检查通过；token 库构建完成、SHA256 固定。

## 第 2 阶段以后（路线，规则在各阶段训练前补全）

1. **20M**：12K 词表从头预训练纯 LM（V4.2 的数据与预算），再做读音后训练。读音组与 LM 对照组比较 `ime-kana-ja-v1` 开发集生成和 Standard 开发集重排。Standard 重排护栏：读音组不低于 V4.2 配方 seed 带下沿 501。
2. **200M**：联合读音预训练，用自己的分数重排；然后按 kd-cont 配方蒸馏到 20M。
3. **口语后训练**：c40 配方，口语数据和口语开发集在本阶段登记。
4. **确认**：预注册，`ime-kana-ja-v1` test 读一次，对照 V4.2 现有部署方式（AzooKey + V4.2 重排）。
5. **Mac / Vime**：重跑批量 KV v4 流程；Vime 合并 AzooKey 与生成候选并统一打分；生成不阻塞按键，沿用中文 2026-11-21 的产品决定（先显示重排结果，停顿后或在后台生成）。
6. **最后**：中日英多语 800M，单独计划。

## 偏差

**D1（2026-11-25，0.2 来源）：从作者级排除改为文档级排除。** WRIME 的 60 位作者全部、JMultiWOZ 65 位用户中的 64 位都已进过以往的评测集或草稿候选池，作者级排除不可行。改为：`artifacts/benchmarks` 下所有以往日文评测集、草稿、审核副本和候选导入里出现过的帖子 / 对话一律排除（19 个文件，8000 个文档），(左文, 读音) 与以往条目相同的也排除。development / test 按作者 / 用户做 seed 随机划分（WRIME 30/30，JMultiWOZ 33/32），两份之间作者不重叠；与以往集合共享作者。规模每份 600 条（WRIME 400 + JMultiWOZ 200）。构建脚本 `scripts/ja/benchmarks/prepare_kana_ime_ja.py`，seed 20261125。

**D2（2026-11-25，0.2 重叠检查）：先冻结，第 1 阶段在训练侧去重。** 冻结时扫描的是现有日文训练文本：`corpus-fast-v1` 训练集 2,518 万行和 `corpus-v41-chat` 48.2 万句，命中 45 条，在抽样前去掉。第 1 阶段新增的文本（FineWeb-2 等）不再回头改动已冻结的集合，而是在构建时去掉与本集消息重叠的训练文档，用同一套扫描方法，去重数登记在第 1 阶段。不足 12 个规范化字符的消息不在扫描范围内。

**D3（2026-11-25，0.2 指标定义的补充说明）：** 书写形式宽松判定按候选与每个参考答案逐一调用 `notation.relation`，结果为 `=` 或 `A` 即算对。答案不在 AzooKey 池中时，书写形式变体同样算对；生成候选在池外，所以只能这样判。`notation.error_class` 的旧口径会把这类情况记为池外，因此本页的宽松数会略高于以往报告。

**D4（2026-11-25，1.3 读音规则）：已知分歧表。** 整段读音不一致的片段不再一律排除在读音样本之外。两种读音按词比较：在两种分词共有的字符边界处切开，每个最小片段先规范化（去掉符号读音和非假名字符，ヂ/ヅ 归并为 ジ/ズ）。所有片段一致，或者每个不一致的（写法, UniDic 读音, Sudachi 读音）三元组都在 `configs/ja/ja-reading-table.tsv` 里时，该片段成为读音样本，读音按表取。表由 `scripts/ja/corpus/reading_pairs.py` 构建：

- **分歧对**：seed 20261127，V4 LM 语料、V4.1 聊天、`ja-gen-export-v1` 各 100,000 句（来源和句子规则同 1.2）；可输入句 216,348 句，不同的分歧三元组 2,065 个。
- **LLM 判定**：两轮，两种读音的展示顺序相反，每条附最多三个例句。选项：其中一个读音、两者皆可（再给出更多用户会输入的那个）、取决于语境、都不对。两轮一致的判定：Sudachi 1,069，UniDic 337，两者皆可 30，取决于语境 29，都不对 23；两轮不一致 577。
- **收录**：只收出现至少 3 次的三元组（357 个），去掉不超过两个字的单汉字词和人工排除项（共 37 个）。收录的三元组全部经过人工复核（`configs/ja/ja-reading-review.toml`）：人工指定 94 个写法的读音，其中 22 个纠正两轮一致的判定（多为选了不连浊或较少见读法的 UniDic 判定，如 意気込み イキコミ、御社 ゴシャ），72 个处理两轮不一致的对；10 个读音取决于句子或人物的写法被排除。结果 303 行（Sudachi 186，UniDic 11，两者皆可 10，人工 96）。含表外分歧三元组的句子仍只作普通 LM 文本。
- **效果**（1.2 样本，6,843 个可输入句）：原始一致率 94.8%，规范化后 97.0%，加表后 99.0%（LM 99.0、聊天 99.7、FineWeb-2 98.5）。1.2 样本与分歧对样本取自相同来源、seed 不同，可能有相同句子。
- **字典固定**：只要装了完整版 `unidic` 包，fugashi 就会加载它而不是 unidic-lite；`readings.py` 现在遇到 unidic-lite 以外的字典直接报错。

**D5（2026-11-25，1.3 读音规则）：两本字典一致、但用户很少这么打的读音。** 1.3 试构建时发现两本字典在这些词上是一致的：私 ワタクシ、日本 ニッポン、明日 アス、句末 言う ユウ，以及 何 ナン（连 を/が/か 之前也是，何をする 读成 なんをする）。在 18.9 万条试构建样本里，私 ワタクシ 出现 1,353 次，私 ワタシ 一次也没有。D4 只处理不一致的读音，不改的话这些最常用词的读音样本几乎全是这种读法。规则：片段恰好是这些词时，把一致读音换成用户实际输入的读音——私 → ワタシ（后接 共/ども 时不换，私共 仍是 ワタクシドモ），日本 → ニホン，明日 → アシタ，言う ユウ → イウ，何 → ナニ（后接 だ/で/と/の/て/な/じ 时保留 ナン）。规则在 `scripts/ja/corpus/kana_samples.py` 的 `AGREED` 里，来源是逐个看试构建样本中最常见的 1,500 个汉字片段读音，加上常见多音词的抽查；列表里其他词的读音都与用户输入一致。日本一 这类复合词（Sudachi ニッポンイチ，UniDic ニッポン + イチ）因此变成不一致，不作读音样本。`ime-kana-ja-v1` 按字典读音冻结，development 中约 24 条的输入用了这些读音（私 8、明日 6、何 9、日本 1，其中一部分本来就对）。评测集不改；第 2 阶段单独报告这些条目。

## 第 2 阶段登记（2026-11-26）

训练器 `src/vimeml/training/joint_ja_kana.py`（入口 `scripts/ja/training/train_ja_kana.py`）：每次更新按配比从各种类取样，种类内的顺序是按 (seed, 种类, 轮次) 生成的双射，任一步的批次只由 (seed, step) 决定；数据并行时各进程取同一全局批次中各自的行，按全局监督 token 数归一化，梯度与单卡相同。检查点沿用 zh13 / zh200m 格式。`tokens` 归一化 = 全部 token 等权；`per_kind` = Σ (该种类条数 / 批大小) × 该种类平均损失。所有运行只用 final.pt，不按开发集挑检查点。

**2.1 20M**（12K / d384 / L9，20.0M 参数）。

- **预训练**：随机初始化，V4.2 的预算 1,081,942 次更新，每次 `plain` 466 + `chat` 46，token 归一化，余弦 6e-4 → 6e-5，warmup 1,000，前缀裁剪 0.30。4 个 seed：1219827974（V4.2 的 seed）、20261126、20261127、20261128（`configs/ja/train-ja-kana-20m-pt-s{1..4}.toml`）。
- **读音组**（`train-ja-kana-20m-read-s{n}.toml`）：从各 seed 的预训练 final.pt 继续（只取权重，AdamW 重新开始），中文 r2-cont 配方：60,000 次更新，余弦 1.5e-4 → 1.5e-5，warmup 1,000，seed 20261130；每次 `plain` 175 / `chat` 17 / `span` 192 / `sentence` 128，`per_kind`。
- **LM 对照组**（`train-ja-kana-20m-lm-s{n}.toml`）：同一起点、同一调度，每次 `plain` 466 / `chat` 46，token 归一化。
- **评测**（训练结束后，只用开发集）：
  - `ime-kana-ja-v1` development：最终列表 = AzooKey N-best 20 ∪ 按键位分桶的 beam 16 生成（前 10），按 生成分 + λ × LM 分 排序，λ 从 1.6 起只在开发集上调。主指标为书写形式宽松 Top-1；另报严格 Top-1、Top-3、按长度和左文分组、D5 条目单独列出，按作者 / 对话聚类统计。LM 对照组不会生成，只用 LM 分重排 AzooKey 池。
  - Standard development（728 条）：读音组和对照组都只用 LM 分重排。
  - 每个 seed 单独报告，并报 4 个 seed 的均值。
- **判定**：读音配方保留的条件是 (a) 读音组在 kana development 上宽松 Top-1 的 4-seed 均值高于 V4.2 重排（85.2），也高于 LM 对照组（按 seed 配对）；(b) 读音组 Standard 重排的 4-seed 均值不低于 501。不满足时记录结果，在 20M 蒸馏之前另行登记修正；200M 不受影响。
