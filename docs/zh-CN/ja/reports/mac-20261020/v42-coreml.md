## 5. 测量

`scripts/ja/deployment/measure_v42.py` 用 `xcrun coremlcompiler` 编译每个包，然后每个模型每轮在一个全新的 Python 进程中通过 `coremltools.models.CompiledMLModel` 以 CPU_ONLY 加载 `.mlmodelc`。八个模型交替五轮，每个形状 5 次预热和 50 次计时调用，token ID 为固定种子的随机值。内存为 `proc_pid_rusage` 给出的 macOS `phys_footprint`；增量从 `coremltools` 导入之后的点开始计（Python/coremltools/PyTorch 运行时约 282 MiB）。

条件：接交流电（充电 55→58%），低电量模式关闭，`pmset -g therm` 在六个检查点都没有热或性能警告。测量前质量评估已经结束，没有其他任务在运行；运行期间 1 分钟平均负载从 10.7 回落到 4.3。这些是 Mac 宿主进程的数字，不能替代 iPhone、模拟器或键盘扩展上的测量。

## 7. Chunk KV 图

单 token 图让预填充每个 token 一次调用（§5）。`vimeml.deployment.v4_chunk.KVChunkGraphV4` 导出同样的权重，每次调用处理 T 个新 token；`KVStepGraphV4` 及其包和记录不变。接口：`input_ids int32[1,T]`（1≤T≤128，动态）、`position int32[1]`（当前缓存长度；调用方保证 position+T≤128）、`key_cache`/`value_cache float32(7,1,6,128,64)` → `logits float32[1,T,8192]`、`new_key_cache`、`new_value_cache`。格式 `vimeml_coreml_v4_kv_chunk_v1`；iOS 18，FP32 计算，CPU_ONLY。

缓存写入使用 V2.1 `kv_cache.CacheGraph` 的 `index_put` 模式（转换后为 14 个 `scatter_nd` op）。用它转换和所有门槛都通过，所以不需要 one-hot matmul 备选方案。按绝对查询位置 gather 的静态 128×128 因果掩码让查询 p+i 只看到 ≤ p+i 的槽位，也同时隐藏了未使用的尾部槽位。导出前，trace 出的图在调度 [1,3,124]、[128]、[3,1,124]、[124,3,1] 和 [127,1] 下与 `model(ids)` 和 `forward_cached` 一致（logits 和两个缓存，3e-4），覆盖了从 0 开始、非零开始和最后一个槽位。

## 8. iOS 模拟器与 iPhone 测量

客户端集成在 Vime 分支 `claude/v42-lm-measure` 上（从 `origin/main` `7e8bccc` 建的独立 worktree；只有本地提交）。`VimeLanguageModel` 新增显式的 `Variant`（默认 `.v21`，需显式启用 `.v42`），用来选择资源名、manifest 格式（`vime_ios_lm_v4`）、词表 8,192，以及 V4 保留的转换标记 4–6。这些标记在打分/beam 输入中被拒绝，并从下一词和 beam 输出中排除，与 Python 端的 V4 约定一致。所有生产调用点仍构造默认的 V2.1 模型；只有测试和基准传入 `.v42`。客户端只加载 INT8 无状态模型；KV 图没有集成。

第一次 V4.2 模拟器运行中，五个 V4.2 测试全部失败：原生 SentencePiece 桥接层写死了 16,384 个 piece 的检查，所以 `vime_sp_load` 拒绝了 8,192 个 piece 的 V4 tokenizer。两个 tokenizer 其余的规范化设置相同（identity，byte fallback）。桥接层现在按变体接收期望的 piece 数，检查仍是精确匹配。`Scripts/install_v42_resources.py` 从 `client-resources-v1` 安装经过哈希校验的 V4.2 资源；`validate_model_resources.py` 在其 manifest 存在时也会校验它们。

功能检查（iPhone 18 Pro Max 模拟器，iOS 27.2，Debug）：5/5 个新 V4.2 测试通过。原生分词与全部 6,755 条 fixture 一致，联合后缀分数与 Mac Core ML INT8 相差 0.002 以内（有无转换缓存），第一个 beam 结果在 token ID 和文本上与全部 20 个 Mac 前缀一致（求和相差 0.005 以内）。字面量 `<CTX>` 输入被拒绝，保留 ID 从不出现在输出中。现有 24 个 V2.1 模型测试不加修改通过。分支上完整的 `VimeKeyboardTests` 执行了 381 个测试：13 个跳过（需显式启用的基准/内存场景），4 个失败，共 9 个断言失败（一个智能候选配置断言、一个个人记忆召回延迟预算、一个设置页布局宽度和一个分段转换正字法期望）。在干净的 `origin/main` `7e8bccc` worktree 上，同样四个测试以同样九个断言失败，所以它们早于本次改动；没有修改它们。

模拟器基准：`VimeLanguageModelBenchmarkTests`（负载不变：固定长度 `predict`、20 个词典重排用例 × 5、10 个 prompt × 3 次 beam 和下一词请求），优化 `-O` 构建，`CPU_ONLY`，每个测试进程一个变体，变体交替四轮（`Scripts/benchmark_lm_variants.py`）。每次运行开始和结束时模拟器报告热状态 `nominal`、低电量模式关闭；Mac 接交流电，无热警告；宿主 1 分钟平均负载从 8.8（刚构建完）降到 5.9。四个进程各自 p50 / p95 的中位数：
