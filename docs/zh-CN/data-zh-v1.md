# vimeml-tiny-zh-v1语料（进行中，2026-11-05）

vimeml-tiny-zh-v1 是中文模型，单独训练，计划规模约 20M 参数：d384，上下文 128；词表比较 8K（L10）和 12K（L9），见 [tokenizer 词表对比](reports/zh-v1-20261106/tokenizer-vocab.md)。本页记录语料的来源、规则过滤（stage A）和人工审核队列。质量打分（stage B）和最终导出尚未开始，所以本页数字都是中间状态，不是冻结语料。

## 繁体与地区用语

- 判定方法：先求出一个字集，即会被 OpenCC `t2s` 改写的汉字；某篇文档的汉字中，这类字超过 8% 即判为繁体。
- 判为繁体的文档统一用 OpenCC 1.4.2 的 `tw2sp` 转成简体。这一步同时转换台湾用语，例如 軟體→软件、網路→网络、影片→视频。
- 转换后的文档标记为 `script=hant`。自动保留的文档中有 445 万篇是转换来的，约占 15%。
- 模型只学简体输出，繁体支持留给输入法层面的转换。

## Stage A 规则过滤

规则在 `src/vimeml/corpus/zh_filter.py`，词表和域名在 `configs/zh-filter-terms.toml`，运行和统计用 `scripts/corpus/zh_stage_a.py run|dedup|report`。每篇文档得到三种结果之一：

- **删除**：属于以下任一情况：
  - 黑名单顶级域名；
  - 第一档域名（境外政治媒体）；
  - 主机名带博彩拼音（`.gov.cn`、`.edu.cn` 不受此条影响）；
  - 冒充政府的主机名，例如 `x.gov.cn.spam.cn`；
  - 命中一个强词，或命中两个不同的词；
  - 汉字少于 100；
  - 汉字占非空白字符不到 40%；
  - 重复行占比超过 30%。
- **送审**：没有触发删除，但只命中一个弱词，或属于第二档域名（港台主流媒体）。弱词是常见词，例如菠菜、赌场、色情、台独。
- **保留**：其余文档。

政治类词表是 v0 草稿，不是权威名单。输入法上线前，还应在输入法层面接一份持续维护的审核词表。

博彩 SEO 搭配词（例如 pk10、彩票平台、娱乐官网、备用网址）的选择依据如下：

- 来源：2026-11-05 在 3 个分片、共 380 万篇文档上的试跑，加上首批人工标注。
- 试跑中正常文本也常用的词没有收入，例如开奖、快三（“快三年了”）、充值、六合、电投（“国家电投”）。
- 有歧义的四个词只作弱词，例如娱乐平台、电子游艺。

**垃圾网站**由 `report` 统计，满足以下任一条件即列入：

- 一个主机至少有 20 篇文档，其中至少 30% 因命中词被删；
- 一个注册域名下有至少 10 个主机，而且域名标签字母和数字交替至少两次，例如 `u07bgqr7k.com`。

垃圾网站上剩下的文档会整体删除，不进审核。首批人工标注中，这两类文档没有一篇是有价值的正文。

`spam_allow` 是人工核对过的白名单：cool3c、土巴兔、39 健康网、摇篮网。

## 人工审核队列

审核队列由本地的队列导出工具生成，每批 200 条。人工审核相关的代码（队列导出、审核页面、标注合并）只保存在本地，不进仓库。生成方式如下：

- 从送审文档中去掉精确重复和垃圾网站上的文档；
- 按 id 排序后用固定种子 20261105 打乱，所以只审完一部分也是随机样本；
- 所有候选都导出，不做抽样。

review-v2 的规模：

- 一共 954,758 条、4,774 批；
- 按送审原因：单个弱词 663,551 条，第二档域名 298,655 条，两类有少量重叠；
- 另有 70,702 篇在垃圾网站上，直接删除，不进队列。

标签只有三个：保留、不保留、不确定。审核标准如下：

- **保留**：命中的词只是正常用法，而且全文干净。
- **不保留**：只要出现博彩、色情、广告插入、乱码拼接或关键词堆砌，就不保留，不管正常内容占多少。
- **不确定**：实在拿不准时选。

标注工具有两种：静态原型页面和在线审核服务。在线审核服务导出 `labels.jsonl`，每行 `{"id", "batch", "queue", "reviewer", "label", "t"}`。

两种标注都用本地的合并工具合并，并统计双人一致率。标注按文档 id 记录，所以队列重新导出后，同一篇文档的旧标注仍然有效。

## LCCC 聊天（lccc-v2）

`scripts/corpus/zh_lccc.py` 的处理步骤如下：

1. 去掉逐字分词留下的空格，只保留拉丁字母或数字之间的空格。
2. 按与网页相同的阈值做繁简转换，并套用同一份词表：命中删除，只命中一个弱词的单独存进 `review.jsonl`。
3. 每一轮发言作为一条序列，格式为 BOS + 发言 + EOS。
4. 训练集中，10 个字及以上、且出现在验证或测试集的发言会被删掉。更短的常用回复，例如哈哈、谢谢、好的，不算泄漏，保留在训练集。
5. 一条发言重复 n 次时保留 ⌈√n⌉ 份，例如哈哈 41,089→203、谢谢 37,718→195、晚安 20,291→143。这样能压住刷屏，同时保留常用回复之间的频率顺序。

| 划分 | 发言 | 字数 |
| --- | ---: | ---: |
| train | 16,326,323 | 2.09 亿 |
| validation | 56,620 | 67.7 万 |
| test | 28,852 | 34.7 万 |

- 训练集共 1489 万条不同的发言。
- 因与验证或测试集重叠而删掉 129,468 条。
- 因命中词删掉 125,742 条，送审 3,129 条。

## 最终导出（zh-v13-export-r1）

`scripts/corpus/zh_export.py` 把语料导出成上传用的 zstd（level 9）Parquet，输出在 `outputs/zh-corpus/export-r1/`：

- `web`：stage-a-v2 判为保留的文档，去掉精确重复，再去掉垃圾网站和垃圾农场上的全部文档（规则与 `zh_stage_a.py report` 相同，`spam_allow` 里的域名豁免）。
- `review`：审核队列里的文档，只收所有票都是保留的（规则见下文“待做”）。通过名单由本地的审核工具生成，不进仓库。
- `chat`：LCCC v2 的 train、validation 和 test。`review.jsonl` 不导出。
- `finish`：生成 `SHA256SUMS` 和 `manifest.json`。manifest 记录各输入文件和脚本本身的哈希。
- 网页和审核文档按 `sha256('zh-v13-validation\0' + id)` 固定抽 0.05% 进 validation。这个划分只取决于 id，以后追加分片也不会变。
- 每个文件约 4GB 原文，压缩后 1.6–1.8GB。下载失败时只需重下一个文件。
- 列：网页和审核文档是 `id, host, script, han, text`；聊天是 `text, dialogue, turn, script`。

2026-11-06 导出了 web 和 chat 两部分：

| 部分 | train | validation | 汉字（train） |
| --- | ---: | ---: | ---: |
| 网页（自动保留） | 29,217,343 篇 | 14,681 篇 | 308.7 亿 |
| LCCC 聊天 | 16,326,323 条 | 56,620 条（test 28,852 条） | 2.09 亿字 |

- 网页输入 30,035,226 篇。删掉精确重复 7,121 篇、垃圾网站 561,870 篇、垃圾农场 234,211 篇。
- 共 42GB：train 39 个文件，validation 22 个，test 1 个。最大的文件 1.82GB。
- 审核部分和 `finish` 要等审核完成后再跑。

以后追加分片时，另建新版本（例如 r2）：只导新分片，并对 r1 做跨批次精确去重。r1 不改。
