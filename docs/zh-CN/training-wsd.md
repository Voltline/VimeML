# WSD 调度实验（V4.2-50ep、V5-50ep）

两次运行把 V4.2 与 V5 的 cosine 调度换成 WSD（Warmup-Stable-Decay），检验调度能否在不改数据、模型的前提下继续降低 BPC，以及更低的 BPC 是否带来 IME 提升。状态：两次运行均已完成 50 轮并做了本地评估。结论是：两种规模的 LM BPC 都创下各自最好成绩，但 IME Top-1 仍在噪声范围内；部署保持 V4.2 第 20 轮，不做 Core ML 转换和设备测量。

## 设计

| 项目 | cosine（V4.2 / V5-30ep） | WSD（本实验） |
| --- | --- | --- |
| 峰值 lr | 6e-4 | 3e-4 |
| 调度 | 1,000 warmup 后全程 cosine 到 6e-5 | 1,000 warmup → 恒定 3e-4 到 85% → 最后 15% cosine 到 6e-5（`stable_decay`） |
| 轮数 | 20 / 30 | 50 |

其余与对照完全相同：数据池、seed 1219827974、batch 512、BF16、fused AdamW（wd 0.1、clip 1.0）、prefix crop 0.30、5% 聊天、架构。

| 运行 | 配置 | 参数 | 数据 | 更新步数 | stable_steps | 训练时间（单张 L20C） |
| --- | --- | ---: | --- | ---: | ---: | ---: |
| V4.2-50ep | [`train-v42-50ep.toml`](../../configs/train-v42-50ep.toml) | 15,070,848 | V4.2 池，50 轮映射 | 2,704,835 | 2,299,110 | 8.1 小时 |
| V5-50ep | [`train-v5-50ep.toml`](../../configs/train-v5-50ep.toml) | 28,385,792 | V4.3 池，50 轮映射 | 5,376,440 | 4,569,974 | 19.2 小时 |

衰减都从第 42.5 轮开始。原计划中的 V4.2-30ep 在第 25.5 轮之前与 V4.2-50ep 完全相同（数据、lr 一致），中途停止，没有产物。

**数据顺序相同。** 50 轮混合计划与原 20 轮（V4.2）、30 轮（V4.3）计划的请求只差 `epochs` 一个字段；每轮映射由 seed + epoch 决定，重叠轮次的每轮窗口数也逐一相等。因此在重叠轮次上，WSD 与 cosine 每轮看到的数据相同，可以按同轮配对比较。50 轮映射的构建脚本没有随运行上传（仓库中的 `prepare_v42.py` / `prepare_v43.py` 把轮数写死为 20 / 30），数据集身份分别为 `8d62f498…`（V4.2）与 `e6df0f46…`（V5）。

**选择 3e-4 的依据较弱。** 选择依据是历史 cosine 运行"按 lr 分桶的逐轮 BPC 增量"，但逐轮增量主要由数据顺序决定：V4.3-30ep 与 V5-30ep 的逐轮 LM 增量相关系数为 0.98；本实验 WSD 与对应 cosine 在重叠轮次上调度完全不同，相关系数仍有 0.81–0.87。所谓 6e-4 区间"停滞"（V5 第 4–5 轮）在 V4.3 的同一轮也出现；第 29 轮的反弹在 lr 仅 6e-5 的 cosine 和 lr 3e-4 的 WSD 中都出现。因此 3e-4 是否最优，这两次运行无法回答。

- 记录的 `code_sha256` 共 90 个文件。`joint_v42.py`（放宽为最多 50 轮、记录调度名）与 `joint_v5.py`（记录调度名）已从运行源码导入，现在与记录逐字节一致。`expanded_ime.py` 是 `54d7618` 之前的版本（评测模块，训练不使用）。其余文件与仓库一致。
- 两份 TOML 与记录中的配置完全相等，文件头注释已改写（原注释抄自其他配置）。`cluster_v42.sh` 加入与 `cluster_v5.sh` 相同的 `--config` 解析，可以启动非默认配置。
- 两份 README 的 IME 一行完全相同（"best Standard/728 522 (epoch 29), AJIMEE/200 145 (epochs 20/29/30)"），而且与 V5-30ep cosine 的数字一致，是复制来的，不是这两次运行的结果。集群端的逐轮 IME 记录也没有上传。

## 验证 BPC

| 运行 | 更新步数 | LM BPC | 扩充网页 BPC | 聊天 BPC |
| --- | ---: | ---: | ---: | ---: |
| V4.2，20 轮 cosine | 1,081,942 | 3.045152 | — | 3.122060 |
| V4.3，30 轮 cosine | 3,225,888 | 3.043831 | 3.049611 | 3.128712 |
| **V4.2-50ep WSD** | 2,704,835 | **3.032766** | — | **3.106215** |
| V5 controlled，10 轮 cosine | 1,075,287 | 2.948747 | 2.952379 | 3.084419 |
| V5，30 轮 cosine | 3,225,888 | 2.942180 | 2.945641 | 3.108036 |
| **V5-50ep WSD** | 5,376,440 | **2.931708** | **2.936232** | **3.085076** |

两次运行的 LM BPC 都在第 50 轮达到最佳。15M 模型此前三次 cosine 运行都停在 3.044–3.049，WSD 是第一次低于这个平台。

**不能把差距全部归给调度。** 两组对比都同时改变了调度、峰值 lr 和预算：V4.2-50ep 的步数是 V4.2-20ep 的 2.5 倍（是 V4.3-30ep 的 0.84 倍，但后者数据池不同）；V5-50ep 是 V5-30ep 的 1.67 倍。cosine 下加预算的收益很小（V5 10→30 轮 −0.0065，V4.3 10→30 轮 −0.0052），据此推测，本实验的 −0.010～−0.012 中大部分来自调度或峰值 lr，但没有同预算 cosine 对照，也只有一个 seed，这只是推测。

### 曲线形状

同轮配对差（WSD − cosine，LM BPC）：

| 轮次 | V4.2（对 20 轮 cosine） | V5（对 30 轮 cosine） |
| ---: | ---: | ---: |
| 1 | −0.050 | −0.066 |
| 5 | −0.045 | −0.070 |
| 10 | +0.004 | −0.049 |
| 15 | +0.076 | −0.007 |
| 16 | +0.091 | +0.005 |
| 20 | +0.122 | +0.045 |
| 30 | — | +0.122 |

- **早期领先只反映 lr 更低。** WSD 在前几轮领先 0.05–0.07，是因为 lr 只有 cosine 的一半，瞬时 loss 更低。cosine 的 lr 降到 3e-4 以下后（V4.2 第 10 轮、V5 第 16 轮），领先随即反转，最大落后约 0.12–0.13。早期领先不能预测终点。
- **稳定段很快到达地板。** 第 13 轮到第 42 轮的 29 轮里，V4.2 只降了 0.022（3.1812 → 3.1589），V5 只降了 0.0125（3.0739 → 3.0614），每轮不到 0.001，小于数据顺序造成的单轮波动（去趋势残差约 0.0035）。恒定 lr 下这是预期行为，不说明 3e-4 有问题。
- **衰减段拿回全部差距。** 第 42 轮到第 50 轮（7.5 轮衰减），V4.2 降 0.126，V5 降 0.130。作为参照，cosine 从 lr 约 3e-4 降到终点：V4.2 第 11 轮到第 20 轮降 0.118（9 轮），V5 第 16 轮到第 30 轮降 0.124（14 轮）。WSD 用更短的退火得到同等的回收。不应拿 cosine 最后 15% 比较：那时它的 lr 已低于 1e-4，只拿回 0.02–0.03。

### 聊天域

聊天每轮按 5% token 配额重复采样。cosine V5-30ep 的聊天 BPC 在第 25 轮到最低（3.0771），之后在 LM 仍下降的情况下回升到 3.1080，聊天与 LM 的差距从 0.104 扩大到 0.166。WSD 没有出现这种情形：V5 的聊天 BPC 在衰减段一路下降到第 49 轮的 3.0728，第 50 轮回升到 3.0851，终点差距 0.153，仍低于 cosine；V4.2 的聊天 BPC 在第 50 轮最低。一个可能的解释是：WSD 处在低 lr 的时间（约 7.5 轮）远短于 cosine（lr < 3e-4 的时间约占后半程），而重复数据的记忆主要发生在低 lr 阶段。聊天验证集只有 4,986 条，单轮波动也受数据顺序驱动，这里只做描述。

## IME Top-1（本地 FP32）

评估入口为 [`evaluate_wsd.py`](../../scripts/benchmarks/evaluate_wsd.py)，语义与 V4.2/V4.3/V5 相同：完整词表后缀 logP 求和、上下文与候选联合分词、FP32、关闭 TF32、稳定排序。fixed reference、blind 集与确认评分 v2 的两个集合都未读取。结果在 `outputs/evaluation-wsd-20261024/`。

按事先确定的规则，主候选是 BPC 最佳的第 50 轮。第 42 轮是稳定段最后一个完整轮次，在本地 IME 评估之前选定，作为同一 run 内的对照：与第 50 轮同一条训练轨迹，BPC 高约 0.13，比以往任何模型间对比的 BPC 差距都大。它只用于描述。

### 选点说明

集群说明写的"两个 run Standard 最佳均为 521/728"是在 50 个 epoch 里按 dev 分数挑出的最大值，属于在 dev 集上的选择偏差。V5 的报告里，相邻两轮在 Standard 上就有约 60 题翻转。本地复现的主候选为 506（V5）和 515（V4.2）。

## 结论

1. **WSD 有效降低了 BPC，但没有转化为 IME 准确率。** V4.2 降到 3.0328，V5 降到 2.9317，都是各自规模的最好结果；但调度与预算、峰值 lr 混在一起，单 seed，不能精确归因。IME Top-1 仍在 Standard 503–523、AJIMEE 134–145 的区间内，与 cosine 系列没有区别。这是 BPC 与重排脱钩的第 7 次验证，也是 BPC 差距最大的一次（同 run 内 0.13）。
2. **部署保持 V4.2 第 20 轮。** 两个主候选都没有显著优于它，不做 Core ML 转换和设备测量，不预注册新的确认评分。
3. **训练方面的经验。** 早期领先和稳定段停滞都是 WSD 的固有形态，不能据此调参；比较调度应看衰减后的终点，并在相同预算下比较。WSD 的稳定段 checkpoint 可以分叉衰减，这是今后做同预算对照最便宜的办法，但现有 continuation 机制只接受 cosine 源并要求延长预算，需要改造。
4. **方向不变。** 与 V5 的结论一致，当前"固定 AzooKey 候选池 + 后缀 logP 求和"的重排方式下，继续降低预训练 BPC 不是提升 IME 的途径。

## 结论边界

两组对比都同时改变了调度、峰值 lr 和预算，只能回答"这套 WSD 配置在更大预算下是否更好"：在 LM 上是，在 IME 重排上否。它不能回答同预算下 WSD 与 cosine 谁更好，也不能回答 3e-4 是否是最佳峰值。所有 IME 数字都来自非 blind 的开发集与回归集，只用于描述和否定性结论。
