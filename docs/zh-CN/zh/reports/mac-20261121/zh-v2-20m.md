## 5. 发布门槛评估

1. **Mac 对齐与搜索门槛：** **通过**（无状态 `3.27e-5`，源 `2.48e-5`，INT8 `2.38e-5`，重打分 Top-1 `125/125`）。
2. **Vime 125 例 fixture 门槛：** **通过**（`prompt_ids` `125/125` 完全一致，重打分 Top-1 `125/125`，`max |Δfinal| = 0.5448`）。
3. **真机 60 ms 门槛（iPhone 13 Pro）：**
   - **Rime 重排（当前线上候选路径）：** **通过**（`p50 4.12 ms`，`p95 7.47 ms`，**100% ≤ 60 ms**，与 v1 相同）。
   - **逐键 task 模式生成：** **在 iPhone 13 Pro 上达不到 60 ms**（`p50 51.80 ms`，`p95 134.49 ms`，**56.8% ≤ 60 ms**；125 个按键中 54 个超过 60 ms，因为按键放在 prompt 里时 task 模式无法在击键之间复用逐键 beam 树）。
   - **建议：** v1 和 v2 都打包在 `vime.chineseModelVersion` 开关后面。明天提交时，v2 可以安全地作为 Rime 重排/纠错的默认模型（13 Pro 上 100% ≤ 60 ms），整句生成继续放在开发开关后面，直到 task 模式击键延迟在 13 Pro 上降到 60 ms 以内（如果团队倾向于只在上线整句生成时才发布 v2，也可以继续以 v1 为默认）。
