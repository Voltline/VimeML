# 中文联想本地测试页

用来在浏览器里手动试 `vimeml-tiny-zh-v1`：联想会给出什么、自由续写会说什么、几个候选的分数谁高。不训练，不调用 API，不保存输入，只监听本机。

```powershell
.\.venv\Scripts\python.exe -X utf8 -u scripts/tools/phrase_demo_zh.py
```

出现 Ready 后打开 `http://127.0.0.1:8766/`。默认加载发布目录 `artifacts/releases/vimeml-tiny-zh-v1-hf-v1/inference` 里的 FP32 推理包，与 Hugging Face 上的权重相同；也可以用 `--bundle` 指定别的推理包。CPU 4 线程，`--port` 换端口，Ctrl+C 停止。

**页面显示的是模型的原始输出，没有经过键盘端的关键词屏蔽。** 这正是它的用途之一：检查模型本身会不会主动给出不当内容。屏蔽词表不在仓库里，这个页面也不读取它。

## 三种模式

- **联想**：与[联想基准](../benchmarks/predict-ime-zh.md#解码与模拟的实现细节)同一套解码。beam 16，候选是 2 到 6 个汉字，取分数最高的 5 个互不为前缀的候选，分数是对数概率之和。可以加拼音约束：只打了首个音节，或者每个字的声母（读音来自本地的 rime-ice 单字表；本机没有这份表时约束不可用）。前文每行一条，按训练格式各自成句，放不下时丢弃最早的发言。
- **自由续写**：第 1 条是贪心解码，其余 5 条是采样（temperature 0.8，top-k 50，top-p 0.9，每次生成换一个 seed），重复的只显示一次。不限字符，遇到发言结束符或长度上限（4 到 48 个 token）停止。
- **候选打分**：只用当前输入作上下文，打分方式与候选重排基准相同。页面按分数排序，并给出候选之间按概率归一化的占比。

“接上”把候选追加到当前输入。耗时是开发机 CPU 推理时间（模型已加载），不代表 iPhone 键盘的速度。示例在 `configs/phrase-demo-prompts-zh.json`。
