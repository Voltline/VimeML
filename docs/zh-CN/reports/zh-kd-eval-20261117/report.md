# v2-20m 蒸馏两臂的 development 评测（2026-11-17）

本报告按[蒸馏计划](../../training-zh-kd-plan.md)的判定规则，评测 `kd-base` 和 `kd-cont` 两臂。老师是 12K 联合拼音 200M。参照有三个：

- `vimeml-tiny-zh-v1`，LM 模式；
- 20M 三任务模型 `r2-cont`；
- 200M 老师本身。

所有评测都只用 development，blind 和公开集 test 都没有读。公开集的数字来自集群上的 `cluster_eval_zh.sh` 和 `pinyin_gen_zh.py reprior`。参照模型的数字来自 [200M 评测](../zh-200m-pinyin-eval-20261116/report.md) 那一次运行，用的是同一个后端和同一批输入。

## 结论

- **`kd-cont` 通过判定，成为 `vimeml-zh-v2-20m` 的候选；`kd-base` 没有通过。**
  - 主指标是公开拼音集上用自身分数重打分（λ = 1.6）后的 Top-1：
    - `kd-cont` 为 54.8%，比 v1 单模型高 2.1（p = 0.041），通过；
    - `kd-base` 为 53.9%，只高 1.2（p = 0.23），未通过。
  - 守门是 Standard 全拼重排：两臂都只比 v1 少几题，都不显著（−4，p = 0.63；−6，p = 0.38），守门通过。
- **蒸馏补回了一部分 LM 能力，但不多。**
  - `kd-cont` 用自己的分数重打分，比 `r2-cont` 自己重打分高 1.5（p = 0.025），生成顺序也高 1.8（p = 0.008）。
  - 与老师相比差距仍然很大：200M 自身重打分是 58.8%。
- **联想仍低于 v1。** 轨道 A 的 Top-3：`kd-cont` 25.6，`r2-cont` 24.8，v1 27.6。联想按规则只作描述，但手机上只加载一个模型，所以 v2-20m 的联想会比现在线上的 v1 弱。这一点要写进发布说明，并作为下一轮的改进目标。
- **私有基准结论一致**：
  - `kd-cont` 用自身分数重打分，比 v1 单模型高 2.1（p = 0.003）；
  - 与线上 v1 的做法（Rime 16 句加 v1 重排）相比高 9.3，其中全拼高 4.4（p = 0.003）。发布门槛「全拼不能显著退步」通过。
  - 私有集上 `kd-base` 略高于 `kd-cont`（35.9 对 35.5），差距很小。按计划，选臂看公开集主指标。

## 设置

- **两臂**（详见蒸馏计划）：
  - `kd-base`：从 v1 基座出发，训练 90,000 步，final.pt 的 sha256 为 `bc819588…`；
  - `kd-cont`：从 r2-cont 出发，训练 30,000 步，sha256 为 `412aee1d…`。
  - 两臂都用 α = 0.5、T = 1，只用 r1 数据。
- **拼音生成**：公开集 `ime-pinyin-zh-v1` development，3,444 条输入。
  - 用 [zh_search.py](../../../../src/vimeml/deployment/zh_search.py) 做分桶束搜索，束宽 16，带输入框内的上下文，任务模式。
  - 取前 10 个候选，按 genScore + λ × prior 重排，λ = 1.6，prior 是模型自己。
- **配对检验**：句子簇 sign-flip，20,000 次置换。
- **Standard**：`ime-standard-zh-v1-r1` development 全拼重排，1,456 题。
- **联想**：`ime-predict-zh-v1-r1` development，轨道 A–D。

## 对 v2 的影响

- `vimeml-zh-v2-20m` 的候选定为 `kd-cont`，打分规则是用自己的分数重打分，λ = 1.6。手机上只加载这一个模型。
- 还要过的发布门槛：
  - iPhone 延迟实测；
  - 确认评分。
- 下一轮（第三轮）的方向：
  - 加入 r2 数据；
  - 调整 α 和 T，目标是在生成顺序和联想上进一步向老师靠拢；
  - 同时按[键盘错字计划](../../training-zh-typo-plan.md)，在选定的这一臂上做加不加 `typo` 的两臂对照。
