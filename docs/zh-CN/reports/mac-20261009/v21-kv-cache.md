# V2.1 KV cache（2026-10-09）

从最新VimeML main `0a85a36`、Vime main `1ea4cf8`建立独立实验分支，沿用V2.1 extend5
step40000的冻结bundle、V2 tokenizer、INT8 block32、FP32计算和CPU_ONLY，不训练、不改标签、
不使用blind、不替换为V3。收尾时客户端 main 更新至 `d96d94e`（两处错音候选与
Xcode Cloud 基线资源），已无冲突合入并重跑13项针对性功能检查。性能测量使用 KV 提交
`1c6c433`（基于 `1ea4cf8`）；后续 main 未改动 LM 推理与固定性能工作负载，性能数据沿用原测量。
完整方法与原始报告索引见[英文记录](../../../reports/mac-20261009/v21-kv-cache.md)。

## 实现与边界

最低iOS18，batch1，最多128 token。新增输入为token块`[1,Q]`、已有长度`[1]`与两份FP32
K/V`[6,1,5,128,64]`，输出新token的logits`[1,Q,16384]`及新的K/V快照。
一份完整K/V组合1.875MiB，不含临时内存和分支副本。scatter_nd更新绝对位置，固定causal mask按查询位置取行。

评分按实际联合分词后的公共token前缀预填充一次，再从同一只读快照计算各候选后缀；
下一词和beam只处理新增token，结束的beam释放缓存引用。缓存只活在单次请求中，
请求完成或取消后释放，退格/上下文变更重新预填充，不滑窗或重排学习式位置编码。
保持原suffix logP sum、全词表归一化、无候选最终EOS/截断、稳定并列和词典回退。

单token解码只输出64KiB logits。预填充仍计算前缀所有行，Swift取最后一行后释放其余行，
不在图中增加第二个动态输出切片。新资源与原V2/V1分开；默认仍`.v21`，
显式`.v21KV`或`Configuration/KVCache.xcconfig`启用新版本。

## 失败记录与交付

初版动态mask/select转换失败(max36.85)。固定mask取行曾通过FP32，但拼接缓存版本的INT8全长
输出仍异常(max25.875)，单独移除动态logits裁剪也未解决(FP32 max24.687)。
scatter_along_axis导出遇到形状推断限制；最终index_put/scatter_nd组合通过全部对齐与原生测试。
未隔离单一运行时原因，失败日志/报告和已接受导出器的精确源码均保留。
最终源码新增输入/缓存校验，不改变已接受推理图。

首次模拟器Release构建因KV文件未声明为脚本sandbox输入而失败；独立xcconfig及资源清单修复，
普通构建不要求KV资源。失败与成功xcresult分别保留。

接受产物位于`artifacts/deployment/tiny-ja-v2.1-extend5-kv-{fp32-v5,int8-b32-v2,client-resources-v2}/`。
FP32/INT8包逻辑大小50,382,727/14,355,753字节，压缩32个有限学习矩阵，结构mask与norm不压缩。
报告位于`outputs/deployment/v21-kv-*`。
结果ZIP只迁移新模型、必要编译资源、KV报告及双仓库handoff清单。客户端 main `d96d94e`
已跟踪原V2模型/tokenizer，正常克隆后只需安装KV资源；重新导出仍需前次包中的冻结ML bundle。
代码走独立关联PR，KV模型不提交Git。迁移按路径/数量/大小核验，复用既有模型身份，不反复全树SHA256。
