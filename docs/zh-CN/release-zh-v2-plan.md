# vimeml-zh-v2 发布范围

2026-11-15 起草。本文规定中文 v2 系列发布哪几个模型，哪些工作只算 v2 的研发记录，以及每个模型发布前要过的门槛。各模型的训练规则仍以各自的训练计划为准。blind 和公开集 test 的确认评分要另写预注册计划，本文只定原则。

## v2 包含什么

v2 是 vimeml-tiny-zh-v1 之后的中文模型系列。v2 的模型都能直接**从拼音生成句子**：输入按键，模型直接输出文字，不再只给 Rime 的候选重新排序。按照[三任务计划](benchmarks/predict-zh-plan.md)，同一个模型同时做重排、联想和拼音生成三件事。拼音生成必须支持，所有新模型都必须带 KV 缓存。

### 发布模型

| 发布名称 | 端 | 规模 | 分词器 | 候选来源 | 状态 |
| --- | --- | ---: | --- | --- | --- |
| `vimeml-zh-v2-20m` | 手机 | 约 20M | 12K（与 v1 相同） | 蒸馏版 `kd-cont`，自身重打分（[评测](reports/zh-kd-eval-20261117/report.md)，2026-11-17）；第三轮可能取代它 | 候选，待定版 |
| `vimeml-zh-v2-200m` | 桌面 | 约 200M | 12K | 12K 联合拼音预训练 `zh200m-12k-pinyin-pt`，用自己的分数重打分 | 开发集评测通过（[报告](reports/zh-200m-pinyin-eval-20261116/report.md)），待测延迟和确认运行 |
| `vimeml-zh-v2-800m` | 桌面 | 7.84 亿 | 12K | [zh-800m 训练计划](training-zh-800m-plan.md)，加上拼音能力 | 数据准备中 |

- **20M** 是手机端模型，延续 v1 的部署方式：Core ML INT8、批量 KV 解码、按键位分桶的束搜索。**手机上只加载一个模型**（2026-11-16 决定）：r2-cont 要靠 v1 重打分才好用（见[推理期重打分](reports/zh-pinyin-rescore-20261115/report.md)），等于要加载两个 20M，手机上不可接受。v2-20m 必须用自己的分数重打分，而且要超过 v1 单独用 LM 模式的结果。r2-cont 拼音后训练会削弱 LM 能力，所以它自己打分不如 v1。用 200M（同一个 12K 词表）蒸馏，有望在一个模型里同时得到生成能力和 LM 能力，所以 v2-20m 选哪个要等蒸馏线的结果。
- **200M** 也发布。如果 12K 联合预训练没有通过评估，就改用 200M 基座加拼音后训练（做法同 r2-cont）。这样也算偏离，要在评估报告里写明。
- **800M** 的拼音能力有两种来源：后训练，或者改成联合预训练。具体用哪种，等 200M 的评估结果出来再定（见 800M 计划的“评估”一节）。
- 三个模型都用 12K 分词器，因此可以共用拼音数据、`zh_search` 和 Vime 的接入链路，大模型也能给 20M 做 token 级蒸馏。
- 桌面端的两个模型不考虑手机，也不做 Mac INT8 测试，只测 FP32/FP16 精度和桌面延迟。

### 仍属于 v1 的更新

批量 KV 解码 Core ML 包（v1、v2 两版）、分桶束搜索、v1 的 LM 生成模式，都是 `vimeml-tiny-zh-v1` 的部署更新，模型权重没有变，继续在 v1 名下发布。v2-20m 直接沿用这套运行方式。

## 发布门槛

下面是原则。具体数字和检验方法写进各模型的确认计划，先提交再打开 blind。

1. **拼音生成是主指标。** 在私有基准和公开集 `ime-pinyin-zh-v1` 上测，按全拼、混合简拼、全首字母分别报告，并分别报告重打分开/关、上下文开/关的结果。20M 要跟线上 v1 的做法比较（Rime 16 句加 v1 重排，带上下文），而且全拼不能出现显著退步。桌面端要跟 v2-20m 比较。
2. **重排守门。** `ime-standard-zh-v1-r1` 全拼 Top-1 不能比 v1 显著退步。如果三任务模型自己的重排退步了，线上重排可以继续用 v1，但这一点要在发布说明里写明。
3. **联想只作描述。** 报告 `ime-predict-zh-v1-r1` 轨道 A–D，桌面端要和 v1、200M 默认臂比较，但联想结果不决定能不能发布。
4. **延迟。** 20M 要在 iPhone 上实测（v1 的批量 KV 包目前 iPhone 还没测）；桌面端要在 Mac 上实测完整搜索的 p50/p95。
5. **只确认一次。** 每个发布模型在打开 blind 和公开集 test 之前，先选定候选和打分规则，然后只运行一次。development 上调过的参数（λ、束宽等）冻结后不再改。

## 数据合规

上架中国大陆的数据要求只针对 **v2-20m**。

- **export-r1 和 export-r2 符合同一套标准。** 两批数据用的是相同的规则过滤、词表和垃圾站点剔除（站点名单取两批的并集）。人工和 AI 审核从来只针对送审队列（约占文档的 3%），r1 的绝大部分文档同样没有人工看过：
  - r1 审核后只收全票保留的文档（38.2 万篇），没审到的也删除；
  - r2 不审核，送审文档全部删除，比 r1 更严。
  所以“r2 没有人工审核”不是合规上的差别。
- 20M 现有的预训练和拼音数据都来自 export-r1。蒸馏可以使用 r1 + r2，老师模型学过 r2 也不构成问题（2026-11-16 决定）。
- 客户端过滤由 Vime 负责，相关内容不进本仓库。它是兜底：规则过滤的召回率有限，两批数据都可能漏掉少量内容。
- 桌面端模型（200M、800M）没有这项要求。

## 未决事项

- `vimeml-zh-v2-20m` 定版：当前候选是蒸馏版 `kd-cont`（2026-11-17）。如果第三轮更好就换成第三轮，还要等 iPhone 延迟实测和确认评分。
- ~~200M 用联合预训练还是后训练~~：2026-11-16 定为联合预训练，用自己的分数重打分（见[评测报告](reports/zh-200m-pinyin-eval-20261116/report.md)）。
- 800M 拼音能力的来源，在 200M 评估之后、开训之前确定。
- 默认束宽：公开集束宽扫描完成后定（目前束宽 16 和 12 已有结果，16 显著更好）。
