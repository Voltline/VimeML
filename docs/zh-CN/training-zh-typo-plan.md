# 中文键盘错字：数据、打分与评测计划

2026-11-17 起草。Vime 已经做了整句纠错（2026-11-17）：

- 找出模型打分最弱的 token 窗口，在窗口内对拼写做单字母编辑（替换、插入、删除、交换）；
- 每个编辑后的拼写交给 Rime 整句转换，取首选；
- 用 LM 分数比较原句与纠错句，至少高出 showMargin = 3 才显示，且纠错句不排第一。

客户端工程这一侧已经接近上限，剩下的改进要从模型这边来。本计划在模型侧做三件事，再加一个公开评测集：

1. **训练数据加键盘错字**：新增拼音任务类型 `typo`。
2. **按实际按键打分**：用 task mode 下的 P(句子 | 实际按下的键) 代替“LM 分数 + 手调惩罚”。
3. **导出附带校准参数**。
4. **公开错字评测集**：`ime-typo-zh-v1`，只用公开文本合成。

## 现状

- 现有 `error` 类只覆盖读音错误：误读表里收录的读音和模糊音（见 [zh_pinyin_data.py](../../src/vimeml/posttraining/zh_pinyin_data.py)）。训练数据里没有任何键盘错字，模型从没见过“按键错了、句子是对的”的样例。
- `zh_search` 要求候选与按键严格一致，所以生成本身对错字没有容错，纠错候选全部来自客户端的编辑枚举。
- 编辑惩罚和 showMargin 都是对数概率尺度上的手调值，换模型就要重调。

## 1. `typo` 数据

**来源与切分**：

- 段落就是现有拼音 store 的 pinyin 段落（P1 网页/审核文档和 LCCC 的拼音份额），validation 也用同一份 validation 段落。
- 随机数种子用独立标签 `<key>#typo`。
- 生成结果写成独立目录 `zh-pinyin-typo-12k`，带自己的 manifest。现有五个 store 逐字节不变，已在训练的 800M 不受影响。

**样例格式**与其他拼音类型相同：`[2,4]+上下文+[5]+按键+[6]+输出+[3]`。其中按键是**加了错字的**按键，输出仍是原句。

**错字生成规则**：

- **基础按键**：全拼 70%，混合简拼 30%。全首字母不加错字，因为单个字母的错位基本无法恢复。
- **错字个数**：1 处 85%，2 处 15%。两处错字不能落在同一个音节。
- **编辑类型**：只在字母上编辑，不碰分隔符 `'`，比例如下。

  | 类型 | 比例 | 规则 |
  | --- | ---: | --- |
  | 相邻键替换 | 40% | 换成 QWERTY 26 键上与原字母相邻的一个键（同行左右、上下行斜邻） |
  | 漏字母 | 25% | 删除一个字母 |
  | 多字母 | 20% | 在某个位置插入一个字母：一半是该位置左右键的相邻键，一半是重复前一个字母 |
  | 交换 | 15% | 交换相邻两个字母 |

- **合法拼写**：错字后的按键仍可能恰好是一串合法拼音，比如 `shi` 打成 `si`。这类样例保留，因为客户端最难处理的正是这种情况。manifest 统计里分别记录合法与不合法的比例。
- **比例来源**：编辑类型的比例是先验设定，不从任何私有数据里估计。私有语料只做最终检验。
- **键盘范围**：只做 26 键，九宫格不在本计划内。

**训练混合**：`typo` 作为第五种拼音任务类型，沿用 `per_kind` 归一化。

- 20M 每次更新 48 条，与现有 `error` 的 32 条同一量级。
- 训练器支持从第二个目录读入额外的类型，代码改动在 `joint_zh_pinyin` / `joint_zh200m` 的 `[pinyin]` 段。

## 2. 按实际按键打分

纠错时，原句和所有候选句面对的是**同一串实际按键**。所以打分可以用：

```
taskScore(句子) = log P(输出 + EOS | [2,4] + 上下文 + [5] + 实际按键 + [6])
```

- 前缀（上下文加按键）对所有候选都一样，现有 sequence package 正好适用：先 prefill 一次前缀，再用 `score_continuations` 批量给各候选的输出打分。**不需要新的导出图**，只需要在 VimeML 侧提供参考算法、PyTorch 校验和一份 fixture。
- 显示规则改为：`taskScore(纠错句) − taskScore(原句) ≥ margin`。用 `typo` 数据训练过的模型，会把“这个编辑像不像真实手误”学进分数，删字母这类编辑的可信度不用再手调。
- 只有三任务模型能用，v1 没有 task mode，继续用 LM 规则。

## 3. 校准参数

每个导出在 `RELEASE.json` 旁附一份 `calibration.json`，包含：

- 重打分 λ；
- 纠错 margin；
- 如果仍需要的话，各编辑类型的惩罚。

这些值在 `ime-typo-zh-v1` 的 development 上标定。具体做法：先把干净句里的误显示率卡在 10% 以内，再取有错字 @2 最高的那组参数。Vime 换模型时直接读这个文件。

## 4. `ime-typo-zh-v1` 评测集

**来源**：公开拼音集 `ime-pinyin-zh-v1-r1` 的 development 句子，只取全拼输入。test 部分继续保留，不读。

**每句三个版本**：

- 干净；
- 1 处错字；
- 2 处错字（与训练规则相同，种子独立）。

**候选池**：对每个错字输入枚举所有单字母编辑的拼写，用 v1 分桶搜索取每个拼写的首选，再加上原始按键的前 10。候选池生成一次后冻结在评测集里，所有模型都在同一个池子上打分，结果和模型无关。

**指标**：

- 有错字：纠错后 Top-1 和 @2，分 1 处和 2 处；
- 干净句：误显示率（纠错候选出现的比例），以及首选被改坏的比例。

**检验**：句子簇 sign-flip 配对检验，20,000 次置换。

生成脚本和数据进仓库，规则与公开拼音集相同。

## 判定

全部在 development 上进行。

**20M**：在蒸馏测评选出的那一臂上续训，分两臂：

- 加 `typo`；
- 不加 `typo`，作为对照。

两臂步数、种子、数据顺序都相同。

1. **主指标**：`ime-typo-zh-v1` 有错字 @2。比较的是加 `typo` 的臂用 taskScore 规则，对照臂用当前的 LM 规则（margin 3）。主指标必须显著更高。
2. **守门 1**：公开拼音集自身重打分 Top-1，不能显著低于对照臂。
3. **守门 2**：干净句误显示率不高于对照臂，Standard 全拼 Top-1 不能显著低于 v1。
4. **描述性**：
   - 两处错字各项指标；
   - 合法拼写错字单独的结果；
   - 私有基准（只在本地跑）。

**800M**：等 20M 通过后，在 800M 某次续训时把 `typo` 加进混合数据，记为 800M 计划的偏离。不做单独的后训练，因为拼音后训练会削弱 LM 能力，r2-cont 就是先例。

**200M**：v2-200m 已经定稿，不重训。

## 不在本计划内

- 让 `zh_search` 本身对按键做容错匹配（例如 key 级编辑距离搜索），候选仍由客户端枚举。
- 九宫格错字。
- 进一步压缩客户端时延。
